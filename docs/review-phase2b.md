# Review Phase 2B: pagination and PDF printing

This phase addresses review items 11 and 12.

## End-to-end pagination

- Conversations load the first page and request additional pages when the user
  reaches the bottom. A visible retry/load-more footer remains available.
- Chat initially loads the newest page. Scrolling to the top loads older pages
  while preserving the visible scroll position. Polling merges only the newest
  page and deduplicates messages by ID.
- Notifications combine automatic refresh of page one with load-more for older
  pages. Results are deduplicated and remain ordered by timestamp and ID.
- The To-do board no longer loops over the complete task history. It requests
  independent, bounded pages for To-do's, Dailies and Habits using the server-side
  `section` filter.
- Public reference lookups accept `search`, `page` and `pageSize`, enforce the
  shared maximum page size of 100, and expose paging metadata through response
  headers while retaining the existing JSON-array shape for client compatibility.

## Stable ordering

Conversation, message, notification, task and lookup queries use an ID
tie-breaker in addition to their primary ordering. This prevents duplicate or
unstable records between offset pages when timestamps or names are equal.

## PDF printing

The desktop Reports screen now offers two distinct actions for both required
reports:

- Save PDF uses the existing native file-save dialog.
- Print PDF downloads the same backend-generated bytes and opens the operating
  system print dialog through the Flutter `printing` package.

The macOS development target includes the print entitlement. Windows plugin
registration is generated by `flutter pub get`/the release build.
